Community OpenWrt builds for Cambium Networks enterprise Wi-Fi access points (cnPilot and XV/XE series). Each build is upstream OpenWrt main with a small, reviewable stack of Cambium hardware patches on top, rebuilt automatically every day.

The aim is to keep capable enterprise access points useful on open, maintained firmware, managed by OpenWrt directly or by an OpenWISP controller. This project is not affiliated with or endorsed by Cambium Networks.

Development snapshots. Images are built and checked automatically but are not tested on hardware for every build. Only the models marked validated below have run on real hardware. Always keep a way back to the stock firmware.

Downloads

Each snapshot is a GitHub release with one recovery and one persistent image per family, the family ImageBuilder and checksums. The matching package feed (kernel modules and Cambium packages) is served from this site and is already configured in each image.

How it works

Two images per family

Recovery is a RAM-only image: it boots from memory, writes nothing, and a power cycle returns the access point to its stock firmware. Use it to check that a model works before installing anything. Persistent is installed into the access point's inactive firmware slot. Cambium access points keep two firmware slots; OpenWrt only ever uses one of them, and the stock firmware stays intact in the other as a fallback.

No Cambium files are distributed

The radios need a Wi-Fi board file from Cambium's firmware. These images do not include any. On first boot, the access point copies the board file its own stock firmware uses from the retained stock slot, read-only. Radio calibration is read from the access point's own calibration partition as usual. Neither is ever modified. If the stock slot is missing, the radios stay off and wired networking still works.

Safe boot

On Sage, Cheetah and Jaguar, each boot of a newly installed image is a one-off: until the access point has come up healthy (network, and radios where validated), the next reboot returns to the stock firmware. Only a healthy system arms OpenWrt as the default, so a failed install recovers itself with a power cycle. Thor (XV3-8) boots OpenWrt directly; its stock firmware stays in the other slot for a manual return.

Defaults

  • Stock OpenWrt login: no SSH keys are included and root has no password until you set one.
  • The LAN port is a DHCP client. The access point never serves DHCP or router advertisements onto your network.
  • Persistent images include LuCI, WPA-Enterprise (wpad-mbedtls), 802.11r/k/v roaming (usteer), WireGuard, OpenVPN, LLDP and the OpenWISP agents. Anything else can be added from the package feeds.
  • /etc/openwrt_release shows the upstream OpenWrt version; /etc/cambium-openwrt-release records the family build ID and source commits.

Installing

Read first. You need physical access and ideally a serial console. Back up everything before writing anything, and never overwrite the bootloader, U-Boot environment or ART (calibration) partitions.
  1. Download the recovery and persistent images for the access point's family from the latest snapshot, and check them against the release's SHA256SUMS.
  2. Identify the model. On the stock firmware, the board SKU (see the table above) selects the device tree. The images reject unknown SKUs.
  3. Get a root shell on the stock firmware. Cambium's firmware protects its root shell with a per-device challenge and unlock code. The tool that answers it is not published; please open an issue to ask about access. A serial console with U-Boot access is an alternative route for the recovery trial.
  4. Back up both firmware slots, the U-Boot environment and the ART partition, and copy the backups off the access point.
  5. Trial the recovery image (strongly recommended for untested models). Load it into RAM and boot the model's configuration from the table below. Nothing is written; a power cycle returns to the stock firmware. Check that the model name, LAN, LEDs and, where applicable, the radios come up.
  6. Install the persistent image into the inactive slot only (never the slot the stock firmware is running from), then boot it once. The safe-boot guard keeps OpenWrt only after it comes up healthy.
  7. After the first boot, set a root password, check cat /tmp/cambium-board-data.status (should be imported or present on Thor, Cheetah and Jaguar) and configure the network or OpenWISP as required.

Family installer scripts that automate steps 4–6 are being prepared for publication.

Upgrade & rollback

Upgrading

  • Sage and Thor use the standard OpenWrt sysupgrade with the family sysupgrade.bin, from LuCI, the command line or OpenWISP. Sage writes the other slot and keeps the previous one as a fallback until the new image proves healthy.
  • Cheetah and Jaguar have no generic sysupgrade path yet; reinstall the persistent factory.ubi into the inactive slot.
  • Kernel modules must come from the same snapshot as the running image. The feed for each snapshot is configured in the image; feeds for the two most recent snapshots are kept online.

Going back to the stock firmware

The stock firmware is never overwritten. Selecting its slot in the U-Boot environment and rebooting returns the access point to Cambium's firmware, for example (slot numbers vary by model; check fw_printenv first):

fw_setenv bootcmd bootipq
fw_setenv image 1
reboot

Safety rules

  1. Never overwrite the bootloader, U-Boot environment or ART partitions.
  2. Keep a verified backup of every unit before writing anything.
  3. Boot a new model from RAM (recovery) before installing it.
  4. Treat calibration and manufacturing data as unique to each unit; never copy them between access points.
  5. Keep the stock firmware slot intact until OpenWrt has proven itself on that model.
  6. Untested models: only trial units you can recover locally, ideally with a serial console.
